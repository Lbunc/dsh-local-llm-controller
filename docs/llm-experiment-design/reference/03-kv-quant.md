# 03 · KV 缓存量化（第 2.2 步）

判定门：KV/token × 目标上下文 > 显存余量的显著比例时才扫（`02-offload.md` 2.0）。

## 3.1 档位与取舍

| 档 | 相对 f16 的 KV 显存 | 何时用 |
|---|---|---|
| `f16` | 1× | 质量对照的基准；显存充裕时 |
| `q8_0` | ≈ 1/2 | **默认推荐**：省一半显存，质量损失通常可忽略 |
| `q4_0` | ≈ 1/4 | 需要把上下文断崖大幅推高时；**必须先确认它不损伤能力** |

**排序做法**：

1. `f16` vs `q8_0` 对照 → 确定质量下限
2. `q8_0` vs `q4_0` 对照 → 决定是否值得上 `q4_0`

`q4_0` 的判定关键**不是速度，而是能力是否受损**：用 `09-capability-bank.md` 的能力题做同题对照（唯一变量 = KV 类型）。

## 3.2 质量判定分工（三个问题，三种工具）

> 关键：这三个问题**不能混用同一个工具**，用错会得到假阴性。

| 要回答的问题 | 用什么 | 为什么 |
|---|---|---|
| **"这个改动有没有改变模型输出？"** | `llama-perplexity --kl-divergence` | 对输出分布的偏移敏感，能在极短语料上给出高置信判定 |
| **"哪个模型 / 量化档更好？"** | `llama-perplexity`（PPL） | 同语料同 chunks 下的整体质量对比 |
| **"变了要紧吗？"** | 能力题库（`09-capability-bank.md`） | 只有能力题能回答"是否影响任务表现" |

### ★ `--kl-divergence` 用法

```
# 1) 存基线（对 f16 配置）
llama-perplexity -m <model> -f <corpus.txt> --save-all-logits base.bin -ctk f16 -ctv f16 ...

# 2) 对每个候选配置比对
llama-perplexity -m <model> -f <corpus.txt> --kl-divergence --kl-divergence-base base.bin -ctk q4_0 -ctv q4_0 ...
```

判读规则：

1. **先做控制组**：同一配置对同一配置跑一次（例如 f16 vs f16）。控制组的值就是**工具噪声底**。
   候选档与基线的 KL **必须显著高于控制组**才算"确实改变了输出"。
2. `logits` 文件大小与 token 数近似线性增长，**体积很大** → 用**小块语料**（千级 token）即可，不要喂大语料。
3. 报告里给出：KL 值、控制组噪声底、以及"候选档 vs 基线"的**信噪比**（KL / 噪声底）。

### ⚠️ 不要用 PPL 判 KV 量化

PPL 对 KV 量化引起的分布偏移**不敏感**：偏移会淹没在 PPL 自身的语料/分块噪声里，
甚至出现**符号相反**的结果。**PPL 在这里是假阴性来源**——判定 KV 量化一律用 KL + 能力题。

## 3.3 与其他旋钮的关系

- KV 量化是**省显存的第一手段**，应排在 `-ncffn` 救援之前（`02-offload.md` 2.1c）。
- KV 量化会**改变能撑的上下文长度** → 上下文结论必须与 KV 档一起报（`04-context.md`）。
- 若开启投机解码，**draft 的 KV 档是独立参数**，默认可能比主 KV 档更宽 → 必须先问用户（`07-speculative.md`）。
