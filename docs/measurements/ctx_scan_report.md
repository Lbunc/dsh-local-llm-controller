## 1. 测量方法与通用约束

**环境**：RTX 4070 SUPER 12GB（12282 MiB）、i5-13600KF（6P+8E，20 线程）、llama.cpp b10488（`qwen35moe` 架构，混合 MoE+SSM，40 层仅 10 层有 KV：full\_attention\_interval=4，2 KV heads × 256 维）。

**固定参数**（所有测试一致）：`-ngl 99 -fa on -t 20 -tb 20 -np 1 --temp 0.6 --top-k 20 --top-p 0.95 --min-p 0.0 --repeat-penalty 1 --presence-penalty 0 --slots --metrics`，纯文本（不加载 mmproj），`--reasoning-budget 2048`。端口 55555 / apiKey 留空（header `Bearer dsh-local-llm`）。

**测量方法**（每配置点，一次只变一个变量）：

1. 重启 server（-c C -ncmoe N）→ 等 `/props` 就绪
2. 读**空闲显存**：dedicated/shared（shared 跳升 = KV/编码器溢出，**最可靠的物理信号**）
3. **short 测试** ×2+：`/completion` \~96-160 tokens（首请求含 CUDA graph 捕获偏慢，取稳态）
4. **深填充测试**：多轮对话填充至 \~C-8000，读 `timings`（前缀复用后 `prompt_n` 为增量，eval 速度仍是全深度）
5. **四件套**：t/s + ded/shared + GPU util + CPU util；**含 prefill**（`prompt_per_second`/`prompt_ms`/总墙钟 `prompt_ms+predicted_ms`——大上下文"能装下"未必"能用"，prefill 太慢则不可用）
6. **能力验证**（阶段 B）：agent+编程题库，objective 打分

**可靠性**：异常必重测（后台负载污染最常见）；物理信号 > 速度读数；关键点 ≥2 次重复。测完恢复原配置、杀掉所有测试子进程、释放 55555。

## 2. Qwen3.6-35B-A3B-Uncensored-IQ4\_NL（18.42GB，用户日常配置）

> 特性：qwen35moe MoE（expert\_count>0），40 层仅 10 层有 KV（interval=4，2 KV heads×256），原生 ctx 262144，KV≈5-13KB/token。

### 2.1 卸载（-ncmoe）×上下文扫描（干净环境，确认扫描）

| C     | 空闲 shared | short（稳态）t/s | deep t/s（填充）     |
| ----- | --------- | ------------ | ---------------- |
| 40960 | 142       | 66.2         | 64.1（30.8k）      |
| 49152 | 147\~151  | 69.3/81.0    | 72.7/74.3（39.5k） |
| 57344 | 151\~159  | 71.1/82.8    | 69.9/70.7（43.9k） |
| 65536 | 159\~180  | 79.0/84.0    | 69.3/69.8（52.7k） |
| 81920 | **303**   | 83.5         | 63.5（70.3k）      |

→ **57344\~65536 仅掉 \~4-6%**；81920 shared 跳升至 303MB（KV 溢出开始）。取档：追求极限 65536（余量 \~0.5GB，需关后台），稳妥 49152（\~0.8GB），日常保守 32768（用户最终选择）。

### 2.2 ncmoe 扫描历史（决策依据）

- **ncmoe 16\~26**（@21k 长上下文）：N<20 断崖（shared 683\~1714MB → 25 t/s）；N≥20 shared \~170MB → 49\~71 t/s → 选定 **N=20**。
- **三档 @21k**：20 → 74.1 t/s（余 0.8GB）；22 → 71.8（1.6GB）；24 → 69.6（2.5GB）。

### 2.3 掉速曲线（模型特性，任何配置躲不开）

速度 ≈ 74（≤40k）→ 70（53k）→ 63（70k）→ 60（88k）→ 54（119k）t/s（注意力成本 + CPU 专家瓶颈）。配置 C 只在溢出点之后才影响速度。

### 2.4 视觉编码器（mmproj 858MB）

视觉分水岭 **N=24**（mmproj 858MB + 编码期缓冲需 \~1.6GB 余量）：

- 速度最快 = N=24 @32K（大图 11.8s）；综合上下文+速度 = N=24 @96K（大图 15.2s、deep 49.5，无溢出）。

### 2.5 投机解码（MTP/ngram）——不可用

本模型 GGUF（量化）不含 MTP 层，`draft-mtp` 启动即失败（`model doesn't contain MTP layers`）。ngram 投机无收益（draft 几乎不接受，速度无提升）。**当前 GGUF 上投机解码无可用方案。**

### 2.6 最终配置（已恢复）

```
set MOE_MODE=-ncmoe 20
set CONTEXT_SIZE=32768
set REASONING_BUDGET=2048
（其余：-ngl 99 -fa on KV q8_0 -t/-tb 20 -np 1 temp 1.0 top_k 20 top_p 0.95 min_p 0.0；端口 21113）
```

DSH：contextWindow 32768 / maxTokens 12288（预算 2048 + 回答余量充足）。

## 3. Qwen3.6-35B-A3B-UD-TPM-IQ4\_NL（带 MTP，17.26GB）

> 特性：比Uncensored小 1.16GB、量化更激进（3.9 vs 4.25 bit/param），**带 MTP 头**（`blk.40.nextn.*`）。部分早期结论被本表后续复核修正（首轮误判 + 会话噪声）。

### 3.1 核心发现

- **无 MTP 同配置 \~40 t/s vs 旧版 70-74**（激进低比特解量化开销大）。

### 3.2 MTP × ncmoe × 上下文最优（2026-08 最终）

- **MTP 模式额外 +\~700MB 显存**（draft 缓冲）→ N20+MTP 上下文极限降到 \~48K（无 MTP 时 96K）；**N22+MTP 恰好补偿 → 96K 可用**。
- 无 MTP 时 N20 @32K long \~35-38；**MTP n=2 后 long \~51、deep 22k \~53、接受率 70.5%**。

| 推荐        | 参数                                                          | 表现                                     |

## 5. Qwen3.8-27B（qwen35 稠密混合 SSM，10.18GB IQ3\_XXS）

> 关键判定：**dense（非 MoE）**——`qwen35` 架构，65 层，`expert_count=0`，混合 SSM+注意力，`full_attention_interval=4` → 16 个 KV 层。原生 ctx 262144。

### 5.1 模型特性与 KV 容量

| 特性       | 值                                                |
| -------- | ------------------------------------------------ |
| 层数       | 65（每层 \~160MB）                                   |
| 注意力      | 24 query / 4 KV，key/val=256，KV 层=16              |
| 思考模式     | `enable_thinking` + `reasoning_effort`（默认 xhigh） |
| KV/token | f16=65536B；q8\_0=32768B；q4\_0≈16384B             |

→ 32K q8\_0 ≈ 1GB；权重 10.18GB 加载后 ded≈11.7GB → **只剩 \~0.3GB 给 KV → 32K 已临界**。

### 5.2 上下文断崖（-ngl 99 全 GPU）

| C       | q8\_0 shared | q8\_0 t/s | q4\_0 shared | q4\_0 t/s |
| ------- | ------------ | --------- | ------------ | --------- |
| **32K** | 277          | **24.5**  | 161          | **33.7**  |
| **48K** | 741          | **10.4**  | 242          | 26.3      |
| 64K     | —            | —         | 305          | 22.2      |
| 80K     | —            | —         | 700          | 14.6 ❌    |
| 96K     | —            | —         | 831          | 10.4 ❌    |

→ **dense 32K → 48K 是断崖**（q8\_0 t/s 减半、shared 暴涨）。根因：稠密权重占满显存，无 MoE 专家可卸载腾给 KV。**q4\_0 把断崖推后到 48K**（48K 仍 26.3 vs q8\_0 的 10.4），但未达理论 \~78K（权重占满 + SSM 状态开销）。**实际最佳上下文 = 32K**（q4\_0 33.7 t/s，shared 161MB）。

### 5.3 KV 量化对照（32K）

| KV        | shared | t/s      | 推理题           |
| --------- | ------ | -------- | ------------- |
| **q4\_0** | 164    | **33.0** | ✅             |
| q8\_0     | 309    | 31.6     | ✅             |
| f16       | 1215   | **12.7** | ✅ → 32K 断崖，禁用 |

### 5.4 -ngl 真卸载（32K，q8\_0）——不划算

| -ngl | GPU 层 | ded   | t/s      |
| ---- | ----- | ----- | -------- |
| 99   | 65/65 | 11774 | **29.3** |
| 60   | 60/65 | 11148 | 16.9     |
| 50   | 50/65 | 9877  | 10.2     |

→ 稠密每 token 读所有层，卸载层走 CPU 代价极高（省 0.6GB t/s 腰斩）。早前 `-ngl 90/95` 均 ≥65 层=假卸载（全层仍上 GPU）无差异。

### 5.5 MTP / reasoning\_effort

- **MTP 不推荐**：GPU 已 86%→98% 饱和，draft-mtp 反而更慢（29.5→17.6），shared 顶到 1271MB。
- **reasoning\_effort**：`medium` 思考 563 字符 vs default 1692，答案仍正确（需 server 启动参数，本 build 不接受请求级字段）。

### 5.6 能力验证（32K 最终配置）

多步规划 100%、工具调用编排 100%、LRU 缓存 PASS、有效括号 PASS。能力优秀。

### 5.7 推荐配置

```
llama-server.exe -m .\qwen3.8-27B\Qwen3.8-27B-UD-IQ3_XXS.gguf -a qwen38-27b
  --port 55555 --host 127.0.0.1
  -ngl 99 -c 32768 -fa on --cache-type-k q4_0 --cache-type-v q4_0
  -t 20 -tb 20 -np 1 --reasoning-budget 2048

  --repeat-penalty 1 --presence-penalty 0 --metrics --slots
```

t/s ≈ **33**（q4\_0）；**上下文上限 32K**（48K 断崖）。

## 6. Qwen3.6-35B-A3B-UD-IQ4\_NL（16.80GB，无 TPM）

> 与旧版 Uncensored（18.42GB）**同架构**（qwen35moe，40 层仅 10 层有 KV、256 专家、原生 ctx 262144），仅量化/裁剪更激进（省 1.6GB）。测于 2026-08 干净环境。

### 6.1 架构对照

| 键                     | UD-IQ4\_NL    | Uncensored-IQ4\_NL |
| --------------------- | ------------- | ------------------ |
| architecture          | qwen35moe     | qwen35moe          |
| block/expert/kvLayers | 40 / 256 / 10 | 40 / 256 / 10      |
| context\_length       | 262144        | 262144             |
| 文件大小                  | **16.80 GB**  | 18.42 GB           |
| KV/token(f16)         | 20480 B       | 20480 B            |

→ 架构完全一致，仅文件更小。KV 派生量相同：q8\_0=10240 B/token，q4\_0=5120 B/token。

### 6.2 最佳卸载（-ncmoe，32K / q8\_0，从 20 往下降）

| -ncmoe | 空闲shared | short t/s | deep t/s | gpu% | cpu% |

### 6.3 上下文极限（ncmoe=18）★MoE 几乎不掉速

**q8\_0 KV**：32K=149/63.2 → 48K=229/62.0 → 64K=333/61.2 → 80K=324/61.5 → **96K=723/30.0 断崖** → 128K=1181/24.9。

→ q8\_0 最佳 32K\~80K（96K 断崖）；q4\_0 推到 **160K**（192K 断崖）。**最优快 32K（64.8 t/s）；最长安全上下文 q8\_0=80K / q4\_0=160K。**

### 6.4 上下文极限随 -ncmoe 增大而升高（★关键权衡）

机制：N 越大 → GPU 权重越少 → 给 KV 腾显存越多 → 能撑的上下文越高。

| ctx  | ncmoe18 | ncmoe19 | ncmoe20 |
| ---- | ------- | ------- | ------- |
| 128K | 62.5    | 54.3    | —       |
| 160K | 64.0    | 59.6    | 57.8    |
| 192K | 30.0 断崖 | 51.6    | 55.9    |
| 224K | —       | 55.9    | 55.1    |

| 192K 深填充 | ncmoe18 | ncmoe19 | ncmoe20  |
| -------- | ------- | ------- | -------- |
| 空闲shared | 1101    | 781     | **434**  |
| 填满184K   | ❌超时     | ❌超时     | ✅180K    |
| 稳态eval   | —       | —       | **23.1** |

→ **ncmoe 越大上下文越高**（18/19 在 192K 溢出填不满，20 能填满）；但代价是长上下文速度掉（192K 仅 23.1 t/s）。**★可用上下文 ≠ 能填满**：ncmoe20 在 192K 虽填满，一次请求 wall=263.6s（prefill 占大头），生成 23.1 t/s 却实际不可用。**判"可用上下文"必须看 prefill/总墙钟。**

### 6.5 能力对比：UD vs Uncensored（同参，唯一变量=模型）

32K、q8\_0、rb2048；UD `-ncmoe 18` / Uncensored `-ncmoe 20`，8 题 × 2 次。

| 题                 | UD(18)   | Uncens(20) |
| ----------------- | -------- | ---------- |
| 精确链式/二次优化/多步计算/数论 | 100%     | 100%       |
| 多跳排雷/依赖链          | 100%     | 100%       |
| 反事实核查             | 100%     | 90%（正则偏差）  |
| 条件调度              | 100%     | 100%       |
| **平均**            | **100%** | **99%**    |

→ **能力同档**。唯一 90% 是 Uncensored 一次用英文"Contradiction 3"未命中中文正则——**判分偏差，非能力差**。

### 6.6 KV 量化能力对照：q8\_0 vs q4\_0（同一模型，唯一变量=KV类型）

8 题 × 2 次：**q8\_0 = q4\_0 = 100%**（全对）。→ **q4\_0 对能力无损**，故优先 q4\_0（更省、上限更高）。

### 6.7 推荐配置与选型

```
llama-server.exe -m .\qwen3.6-35B-A3B\Qwen3.6-35B-A3B-UD-IQ4_NL.gguf -a ud35b
```

- **长上下文**：`-ncmoe 20 -c 131072` → 中长 \~55-58 t/s；极限 192K（\~23 t/s，需 prefill 可接受）。
- **能力无损**：q4\_0 KV 对能力 100% 等同 q8\_0（推荐 q4\_0）。
- **选型**：能力 = Uncensored 同档，但更小 → 少卸载 2 层（更快）+ KV 余量更大；普通 ≤128K 用 ncmoe 18（更快），>160K 才加大 ncmoe。**不能同时要"最快"和"最高上下文"。**

## 6.8 Qwen3.8-27B-UD-Q2\_K\_XL（9.15GB，dense，比 IQ3\_XXS 更小）

> 与第 5 章 IQ3\_XXS（10.18GB）同为 `qwen35` dense 架构（65 层 / 16 KV 层 / 原生 ctx 262144 / KV/token f16=65536B），**仅量化更激进（Q2\_K\_XL 9.15GB 省 \~1GB）**。测于 2026-08 干净环境。

### 6.8.1 核心结论（★比 IQ3\_XXS 能撑更高上下文）

**省下的 ~1GB 显存全给了 KV → q4\_0 上下文上限从 IQ3\_XXS 的 48K 提升到 96K**，且速度更快（37 vs 33 t/s）。

| KV 档 | 32K   | 48K   | 64K   | 80K   | 96K   | 112K  |
| ------ | ----- | ----- | ----- | ----- | ----- | ----- |
| **q8\_0** | 36.7  | 37.5  | 27.1 ⚠️ | 10.2  | 14.1  | 13.6  |
| **q4\_0** | 36.5  | 37.1  | 36.6  | 36.6  | 37.3  | 15.0 ⚠️ |

（数值 = short 稳态 t/s；⚠️ = shared 跳升 >300MB 溢出信号。q8\_0 断崖 64K；q4\_0 断崖 112K。）

### 6.8.2 断崖判定（shared 物理信号）

- **q8\_0**：48K=37.5（shared 169）→ 64K=27.1（shared **337**）→ 80K shared 937 → **断崖在 64K**。
- **q4\_0**：32K\~96K shared 146→210（平缓，无溢出）→ 112K shared **382 / 378** → **断崖在 112K**，**最优 96K**。

### 6.8.3 ★可用上下文（prefill/墙钟，跟 IQ3\_XXS 无关的关键差异）

与 35B MoE"极限上下文 prefill 慢到不可用"不同，本 dense 27B **prefill 极快（pps ≈950-1120）**，故 96K 真实可用：

| ctx  | 填充深度 | prefill pps | prompt\_ms | eval t/s | **总墙钟** | GPU | 可用性 |
| ---- | ------ | --------- | ---------- | ------- | -------- | ----- | ----- |
| 64K  | 57214t | 1004.9    | 56938      | 27.0    | 71.7s    | 97%  | ✅    |
| 96K  | 73942t | 952.9      | 77601      | 25.0    | **85.6s** | 97%  | ✅（重测 947.8/85.9s，可重复） |
| 112K | 86989t | 663.1      | 131179     | 16.8    | **143s**  | 99%  | ❌ prefill 掉档，不可用 |

→ **最大可用上下文 = 96K（98304）**：生成 25-37 t/s + prefill \~950 p/s、一次请求 \~86s。112K 时 prefill 掉档、wall 143s，交互/agent 不可用。**"能装下"（KV 断言）与"能用"（prefill/墙钟）在此断崖一致**——112K 是双重不可用。

### 6.8.4 推荐配置

```
llama-server.exe -m .\qwen3.8-27B\Qwen3.8-27B-UD-Q2_K_XL.gguf -a qwen38-27b-xl
  --port 55555 --host 127.0.0.1
  -ngl 99 -c 98304 -fa on --cache-type-k q4_0 --cache-type-v q4_0
  -t 20 -tb 20 -np 1 --reasoning-budget 2048
  --temp 0.6 --top-k 20 --top-p 0.95 --min-p 0.0
  --repeat-penalty 1 --presence-penalty 0 --metrics --slots
```

- **最佳上下文 = 96K（98304）**：q4\_0 下 32K\~96K 速度持平（36.5\~37.3 t/s），取满即 96K 无速度代价。
- **速度优先**：`-c 32768` = 36.5 t/s；**长上下文用 q4\_0 @96K**（30K+ 仍 37.3，3× 上下文）。
- **不与 IQ3\_XXS 冲突**：IQ3\_XXS 上下文 32K（48K 断崖）→ 本模型更大上下文 + 更快，但能力同档。**选型依据 = 需要多长上下文**：≤32K 两者均可；>32K 用 Q2\_K\_XL（能到 96K）。

### 6.8.5 能力对比：Q2\_K\_XL（2-bit）vs IQ3\_XXS（3-bit）@32K

公平规则：同构（dense 27B）/ 同参（-ngl 99 + KV q4\_0 + 32K + rb2048）/ 同题 / objective 判定。精确计算题各 3 次 + 编程题 test cases 判分。**唯一变量 = 量化档（2-bit vs 3-bit）**。

| 题                    | Q2\_K\_XL | IQ3\_XXS |
| --------------------- | --------- | -------- |
| 精确链式（x5=615）        | 100%      | 100%     |
| 二次优化（P=80, 利润 44000） | 100%      | 100%     |
| 多步计算（产线=1131）        | 100%      | 100%     |
| 数论（剩余定理=157）         | 100%      | 100%     |
| 编程 LRU 缓存            | PASS      | PASS     |
| 编程 有效括号             | PASS      | PASS     |
| **平均**               | **100%**  | **100%** |

→ **能力完全同档**。2-bit 量化对这组题无损（都是 27B 同架构，仅 bit 数不同；+数学精确题仍全对）。**注意**：题库偏基础，对梯度较小的量化档**无区分度**；如需验证"2-bit 是否伤能力"，需更高难度题（多跳精确计算/进阶算法），但这不是 32K 上下文场景的重点——选型核心仍是**上下文上限（Q2\_K\_XL 96K > IQ3\_XXS 48K）**。

### 6.8.6 ★投机解码（MTP）——大收益（与 IQ3\_XXS 相反！）

**判定门**：模型带 nextn MTP 头（`blk.64.nextn.*`）+ GPU 未饱和（base long 94%→89%）。**关键差异**：Q2\_K\_XL 比 IQ3\_XXS 更小更轻 → GPU 有空闲给 draft 摊薄，**MTP 大幅提速**（IQ3\_XXS 当时 GPU 86-98% 耗尽，MTP 反而更慢）。

| 模式 | short t/s | long t/s | 接受率 | GPU tail | idle ded | 额外显存 |
| ---- | -------- | -------- | ----- | -------- | ------- | ------- |
| base(无) | 36.5/37.1 | 36.5    | —     | 94%      | 10277   | —       |
| **MTP n=2** | **57.3/57.2** | **51.7** | **63.1%** | 89% | 11173 | +896MB |
| MTP n=3 | 58/55   | 48.2    | 50.1% | 88%      | 11326   | +1049MB |
| MTP n=4 | 57.2/54.6 | 49.8   | 43.3% | 79%      | 11479   | +1202MB |

**复核（重复 ≥2）**：base 36.3 → MTP n=2 **48.1 t/s**（long，+32%），接受率 60.7%，short 56-59。**提升稳定（+32~42%）。**

- **最优 `--spec-type draft-mtp --spec-draft-n-max 2`**：long 51.7 t/s（比 base **+42%**）、接受率 63.1%（>0.65≈优秀）、short +57%。
- **接受率随 n 衰减**（n=2 63% → n=3 50% → n=4 43%）→ **n=2 是甜点**（续 9B 结论：n 越大 draft 越长、验证批量分摊收益递减，n=2 最优）。
- **代价**：额外 +896MB 显存（MTP 缓冲 + 上下文预算），32K 无逸出。

### 6.8.7 推荐配置（含 MTP）——注意 32K vs 64K 权衡

---
**① 文本速度最优（32K）**：
```
llama-server.exe -m .\qwen3.8-27B\Qwen3.8-27B-UD-Q2_K_XL.gguf -a qwen38-27b-xl
  --port 55555 --host 127.0.0.1
  -ngl 99 -c 32768 -fa on --cache-type-k q4_0 --cache-type-v q4_0
  -t 20 -tb 20 -np 1 --reasoning-budget 2048
  --spec-type draft-mtp --spec-draft-n-max 2
  --temp 0.6 --top-k 20 --top-p 0.95 --min-p 0.0
  --repeat-penalty 1 --presence-penalty 0 --metrics --slots
```

**② 长上下文（64K，MTP 上限）**：同上但 `-c 65536`。

- **文本速度优先**：MTP n=2 @32K → 51-57 t/s（比无 MTP 36.5 快 **+32~42%**）。
- **MTP + 上下文权衡**：MTP 额外 +896MB → 上下文上限**从无 MTP 的 96K 降到 64K**（见 6.8.8）。**不能同时要"最快+最高上下文"。**

### 6.8.8 ★MTP n=2 下的上下文上限（= 64K）

MTP +896MB 挤占 KV 余量 → **最大可用上下文 = 64K**（无 MTP 是 96K）。

**短测 shared**（冷启动分配，显 MTP 缓冲+KV 预分配）：

| ctx | short t/s | shared | 判定 |
| ---- | -------- | ------ | ---- |
| 32K | 60.2 | 280 | ✅ |
| 48K | 57.6 | 311 | 临界 |
| **64K** | 59.8 | 439 | ⚠️ 短测信号 |
| 80K | 41.9 | 919 | ⚠️ |
| 96K | 18.0 | 1400 | ⚠️ |
| 112K | 42.5 | 1548 | ⚠️ |

**深填充/墙钟可用性**（真实判据，MTP 增益是否保留 + prefill 是否可接受）：

| ctx | 填充深度 | prefill pps | eval t/s | wall | shared | 接受率 | 可用 |
| ---- | ------ | --------- | -------- | ---- | ------ | ------ | ---- |
| 48K | 30454t | 1079.3 | 48.0 | 32.4s | 277 | 75.8% | ✅ |
| **64K** | 47848t | 998.8 | **41.8** | 52.7s | 310 | 73.8% | ✅（复核 870/41.2/59.8s/71.8%，可重复） |
| 80K | 60895t | 390 | 7.5 | **182.6s** | 786 | 0% | ❌ prefill 掉档+MTP 失效 |
| 96K | — | — | — | 超时>8min | 1134 | — | ❌ 深填充跑不完 |

→ **MTP n=2 最大可用上下文 = 64K**：MTP 增益保持（eval 41.8 vs 无 MTP 的 ~36）、prefill 仍快（~1000 p/s）、wall 52.7s 可用。**80K 即硬断崖**——prefill 掉到 390、MTP 接受率归零、wall 182.6s 不可用；96K 深填充直接跑不完。**注意**：短测 64K shared 显示"溢出信号"（439），但深填充运行时 shared 仅 310——**短测为冷启动分配，不影响真实可用性**；"能装下"用深填充 shared + wall 判定。

## 7. 横向能力对比（跨模型）

- **9B(Q6) vs 27B(Q3) vs 35B(IQ4\_NL,-ncmoe20)**：基础题 9B 92%/27B 96%/35B 96%（无区分度）；GAIA 类复杂题 9B 88%/27B 100%/35B 100%（拉开 9B）。
