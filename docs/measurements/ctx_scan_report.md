# Qwen3.6-35B-A3B 性能调优全历程终版存档

> 本文件为最终定稿。所有数据均已复核；首轮扫描中受后台负载污染的数据已在干净环境下重测修正（见 §4 异常与重测记录）。

## 0. 最终结论速览

1. **最终配置（用户决定）**：`-ncmoe 20` + 上下文 **32768** + 思考预算 **2048**（恢复原始设置）；DSH：contextWindow 32768 / maxTokens 12288。
2. **ncmoe 20 不掉速极限 ≈ 57344~65536**（干净环境实测：57344 掉 ~4%、65536 掉 ~6%）；**81920 起 KV 溢出共享内存**（shared +150~300MB），不再建议。
3. **ncmoe 22 可开 131072**（腾出 ~955MB 显存，干净环境 shared 仅 227MB）；**196608 硬断崖**（shared 1225MB → 19.6 t/s）。
4. **掉速主因是实际对话长度（填充深度），不是配置 C 本身**：填充 ≤53k ≈ 70-74 t/s；70k ≈ 63；88k ≈ 60；119k ≈ 54。GPU 利用率 67→79% 未饱和，瓶颈在 CPU 专家卸载。
5. 决策链：ncmoe 20 被选为速度/稳定平衡点（20=74.1、22=71.8、24=69.6 t/s @21k 长上下文）→ 上下文探索 48K → 复核后确认 32K 恢复。

## 1. 测试环境与方案（方法学）

**环境**：RTX 4070 SUPER 12GB（12282 MiB）、i5-13600KF（6P+8E，20 线程）、llama.cpp b10488（`qwen35moe` 架构，混合 MoE+SSM，40 层中仅 10 层有 KV：full_attention_interval=4，2 KV heads × 256 维）。

**固定参数**（所有测试一致）：`-ngl 99 -fa on --cache-type-k/v q8_0 -t 20 -tb 20 -np 1 --temp 1.0 --top-k 20 --top-p 0.95 --min-p 0.0`，纯文本（不加载 mmproj），`--reasoning-budget = C/2`（探索期）。

**测量方法**（每配置点）：
1. 重启 llama-server（-c C -ncmoe N）→ 等待 /props 就绪
2. 读**空闲显存**：`Get-Counter '\GPU Adapter Memory(*)\Dedicated/Shared Usage'`（KV 缓冲启动时按层分配，放不下溢出到共享内存 → shared 上升 = KV 溢出的物理信号）
3. **short 测试** ×2：`/completion` 96 tokens（第 1 次含 CUDA graph 捕获偏慢，取第 2 次）
4. **深填充测试**：7 轮对话构造（prompt_4k.txt 为 assistant 内容）填充至 ~C-8000，`reasoning_effort=high`，max_tokens=128，读 `timings.predicted_per_second`（注意：前缀复用后 `prompt_n` 为增量，eval 速度仍是全深度）
5. **GPU 利用率**：nvidia-smi `-l 1` 采样，取生成阶段尾部均值

**噪声控制**：每点 2×short；关键点 2×deep；首轮扫描发现后台负载污染（浏览器/任务管理器占显存与 CPU）→ 干净环境重测全部关键点。

### 2.7 视觉编码器（mmproj f16 858MB）扫描（2026-08，独立实验）

**方法**：-ngl 99 / -c 32768 / KV q8_0 固定，变 ncmoe ∈ {20,22,24}，均加载 mmproj；每点测空闲显存 + 文本 short×3 + 小图（256×256 ≈1024 tokens）+ 大图（4.2MB 照片 ≈3032 tokens）+ 22k 深填充。两轮独立测量（vision_sweep + confirm_vision，第二轮关思考验证内容正常返回）。另测视觉+大上下文探针。

| 配置 | 空闲 ded/shared (MiB) | 小图编码 | 大图编码 | 文本 deep t/s | 结论 |
|---|---|---|---|---|---|
| N=20 @32K | 11801~11847 / **703~1072** | 8.7~10.7s | **73~81.5s** | 66~67.8 | mmproj 落共享内存，视觉不可用级 |
| N=22 @32K | 11531~11633 / 147~148 | 2.7s | 18.6~23.2s | 60.7~61.2 | 可用；编码时 shared 涨至 ~300 |
| **N=24 @32K** | 10661~10733 / 132~149 | **2.9s** | **11.8~11.9s** | 61.9~62.6 | **最优**：mmproj 完整进 GPU，编码全程无溢出 |
| N=22 @64K | 11795 / 230 | — | 48.2s | 55.8 | 编码时 shared 飙至 626 → 不可用级 |
| **N=24 @96K** | 11455 / 198 | — | 15.2s | 49.5 | 可用：3× 上下文，图片略慢 |
| N=24 @128K | 11794 / 308 | — | 48.9s | 39.1 | 显存紧，编码退化 |

**结论**：
- **视觉分水岭 = N=24**：mmproj 858MB + 编码期额外缓冲需要 ~1.6GB 显存余量，只有 N=24（腾 1.7GB）满足；N=22 在 32K 勉强可用（编码时 shared 涨），一开大上下文就崩。
- 图片 token 开销：小图 ≈1024（--image-min-tokens），大图 ≈3032；重复同图请求 0.1s（KV 前缀复用）。
- 文本速度受 mmproj 影响很小（N=24 带视觉 deep 62 vs 纯文本 ~70 同填充，含 ncmoe 代价）。
- 视觉推荐：**速度最快 = N=24 @32K**（大图 11.8s）；**综合上下文+速度 = N=24 @96K**（大图 15.2s、deep 49.5、无溢出）。

## 3. 结论与机制

1. **KV 溢出机制**：KV 缓冲启动时按层分配（legacy cache，`kv_unified=false`）；权重 + KV 超 12GB 时部分 KV 层落共享内存/CPU，生成每步跨 PCIe 读 KV → 速度骤降（ncmoe<20 时 25 t/s；196608 时 19.6 t/s）。**shared 空闲值 = 最可靠的溢出信号**。
2. **ncmoe 机制**：`-ncmoe N` = 前 N 层专家放 CPU，其余 GPU。N 越大腾出显存越多（每 2 层 ~0.9GB），但同填充速度略降（20 vs 22: 63.3 vs 61.1 @39.5k，~3-5%）。
3. **掉速曲线**：速度 ≈ 74（≤40k）→ 70（53k）→ 63（70k）→ 60（88k）→ 54（119k）t/s，属模型特性（注意力成本 + CPU 专家瓶颈），任何配置都躲不开；配置 C 只在溢出点之后才影响速度。
4. **32K 恢复理由**：用户决定回归原始配置；32K 远低于任何溢出点（干净环境 shared 基线 ~150MB），速度全程 ~70+ t/s，思考预算 2048 + maxTokens 12288 保证答案不被截断。
